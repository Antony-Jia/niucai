# niucai 桌面端简化设计稿

日期：2026-10-29 · 状态：设计提案，尚未接入产品

配套预览：[交互设计稿](design/desktop-simplification.html)。页面中的任务、文件、设备均为示例，按钮只改变本地演示状态，不执行真实动作。

静态预览：[任务首页](design/desktop-simplification-home.png) · [任务详情](design/desktop-simplification-detail.png)。原型已用本机 Edge 无头浏览器检查渲染、模拟审批、新建、暂停及 1024px / 390px 下无横向溢出；不代表生产功能或全部无障碍验收已完成。

## 1. 设计结论

把产品从“系统功能目录”改成“交代事情、查看进度、拿到结果”的工作空间。

日常主导航只保留 **任务、文件、设备**，设置固定在底部。任务页直接成为首页，不再另设 Dashboard。用户不需要先决定应该创建会话、Goal 还是白板卡片。

一句话使用方式：**告诉 niucai 你要做什么，需要你时再回来，完成后直接看结果。**

补充功能提案：[Bot 工作地图](bot-work-map-design.md)。在任务页提供“列表 / 地图”切换，以像素办公室展示助手工作与白板协作；不新增一级导航，仅完成设计文档，现有 HTML 原型尚未加入地图。

本次交付包含信息架构、页面布局、交互规则、异常状态及实施边界；独立原型覆盖任务列表、任务详情、筛选、新建任务、审批演示、文件、设备和设置。当前产品代码未修改。

## 2. 现状问题与依据

依据：用户提供的首页截图，以及当前工作区 App.tsx、Dashboard.tsx、Workbench.tsx、Goals.tsx、Whiteboard.tsx、Kanban.tsx 和 Bots.tsx。工作区已有进行中的修改，本方案以读取时源码为准。

| 现状 | 对用户的影响 | 设计处理 |
|---|---|---|
| 11 个并列导航，中英文混用 | 不知道先进入哪一个 | 3 个日常入口，统一中文 |
| 会话、Goal、白板、看板分别展示工作 | 同一件事需要跨页追踪 | 一个任务入口，详情内展示进度 |
| 首页四个大数字占据首屏 | 知道总数，却不知道下一步 | 用待处理事项和任务列表代替 |
| “新建会话”只切换页面 | 进入后仍需寻找输入位置 | 首页直接提供任务输入框 |
| 等待确认统计与空状态冲突 | 无法判断是否需要处理 | 统一待处理事项数据和计数 |
| 最近活动暴露 orchestrator.completed | 技术事件缺少实际意义 | 默认展示业务进度，原始事件进入日志 |
| 电脑大卡片长期占位 | 抢占任务空间 | 设备独立入口，任务中按需打开 |
| 最近会话再占一段侧栏 | 与任务列表重复，增加滚动 | 移除侧栏最近会话，列表统一检索 |
| “你的电脑，一直在线。” | 连接异常时仍承诺在线 | 改为“今天想完成什么？” |

源码中特别需要修正：Dashboard 使用 `approvals.data?.length || waiting.length` 统计“等待你确认”，而确认区只显示 approvals。审批为零且任务为 WAITING_HUMAN 时就可能出现截图中的矛盾。WAITING_HUMAN 不应被直接等同为一个审批请求。

## 3. 用户概念与导航

用户只需理解三件事：**任务是要完成的事，文件是成果，设备是执行工作的地方。** 助手是设置中的可选能力，不要求新用户先学习或创建 Bot。

```text
niucai
  任务  ← 默认首页：输入 + 待处理 + 列表
    任务详情：对话与结果 / 进度 / 按需打开电脑
  文件  ← 跨任务查找成果，能返回来源任务
  设备  ← 查看可用性、使用情况与连接问题

  设置  ← 固定底部
    连接 / 助手 / 技能与工具 / 偏好与记忆 / 高级
```

| 旧入口或概念 | 新位置与名称 | 保留方式 |
|---|---|---|
| Dashboard | 任务首页 | 取消独立导航 |
| 会话、Goal | 任务 | 用户层统一；后端实体不直接合并 |
| 白板、Card | 任务详情 → 进度、步骤 | 拆解默认自动展示；手动卡片管理留高级入口 |
| 看板 | 任务列表的可选视图，后续阶段 | 首期只提供列表，旧全局资源看板留高级入口 |
| Files | 文件 | 详情优先展示该任务产物 |
| Memory | 设置 → 偏好与记忆 | 保留查看、纠正、删除能力 |
| 远程 Pi、节点 | 设备 → 执行环境 | 与可操作电脑分组展示，不假装等价 |
| Bots | 设置 → 助手 | 任务详情按需显示参与助手 |
| 扩展 | 设置 → 技能与工具 | 延续原配置与权限 |
| Kernel、WebSocket | 设置 → 连接诊断 | 常态显示连接名，异常用业务文案提示 |
| Attempt、Run、工具调用 | 详情 → 更多 → 执行日志 | 保留诊断能力，默认折叠 |

导航右侧不再显示 1—11 的序号。快捷键放到提示中，不能让用户误以为是未读数量。

## 4. 首页：任务就是工作入口

桌面约 1366×900：左侧 208px 导航；内容区最大 1040px；左右留白 40—56px。删除大面积指标卡、全局活动流和常驻设备预览。

布局顺序：

1. 顶栏：当前工作空间名称，右侧提供任务搜索。连接异常时在这里出现单条提示。
2. 主标题“今天想完成什么？”及输入框；示例提示“整理本周行业新闻，给我一份带来源的摘要”。主按钮“开始任务”。
3. “需要你处理”：有事项时显示，按任务聚合，给出具体原因和“查看并处理”；没有时整个区域收起。
4. “我的任务”：全部、进行中、待处理、已完成筛选。每行只有标题、最新业务进度、状态、更新时间；点击整行打开该任务。

首页不直接放“全部批准”。授权必须打开具体事项，展示对象、动作、范围及影响。待处理卡片和列表可以指向同一任务，但计数来源必须一致。

默认排序：需要用户处理优先，其余按最新活动；已完成任务保留且可筛选。大批量历史采用分页或增量加载，搜索覆盖全部历史而非只搜索当前页。

## 5. 任务详情：一处完成沟通、跟踪与交付

顶部固定：返回任务、任务标题、明确状态、按当前能力提供暂停/继续/取消。取消进入二次确认；不能把关闭详情当作停止任务。

主区约占 2/3，放用户要求、助手关键回复、具体待处理事项和最终结果。输入框固定在内容底部，文案“补充要求或回答问题…”。执行中追加消息需明确显示“已收到，等待处理”，不能暗示立即打断已执行动作。

侧区约占 1/3，展示简洁步骤：已完成、正在做、未开始、受阻。只在确有步骤数据时展示，不编造百分比、预计时间或固定步骤。助手、执行设备、详细日志置于折叠区域。

完成后在主区突出“结果摘要 + 文件 + 来源”，而不是仅显示“执行完成”。没有文件的任务也应交付可读结论。只有独立步骤已结束、但整体仍等待汇总时，不能标成任务完成。

“查看电脑”按需打开侧面板；仅查看不会请求控制权。“接管电脑”显示“正在等待当前动作结束”，收到服务端确认后才能显示“你正在控制”；交还后也须等待服务端确认。离线、权限不足或状态过期时禁用实际控制。

## 6. 新建任务和执行选择

默认只填写要求，不要求选择 Goal、执行引擎、Bot、白板或节点。附件入口只在现有上传能力可用时出现，不因设计稿而宣称 Browser 已支持上传。

“执行选项”默认折叠：指定助手、指定执行环境、授权方式；沿用现有策略，不通过简化界面自动开启 Shell、免审批或设备动作。

拟议路由规则：由明确配置的工作空间默认执行路径决定新任务类型。编排已启用且资源满足条件时可以走 Goal；否则使用仍可用的会话路径。若两者均不可用，保存草稿并给出“完成运行配置”入口。不得在已提交后偷偷切换引擎并重复执行。

提交前检查连接与必要配置。失败保留输入，明确可重试；提交中禁用重复提交；成功才跳转到新任务。未来适配层需提供幂等创建，不能仅依赖按钮防抖。

## 7. 状态与确认规则

| 用户看到的状态 | 条件或含义 | 推荐动作 |
|---|---|---|
| 等待开始 | 已排队，尚未执行 | 查看；支持时取消 |
| 进行中 | 服务端确认在执行或编排 | 查看进度；支持时暂停 |
| 需要你处理 | 有可追踪的审批、问题或阻塞事项 | 查看并处理 |
| 等待资源 | 没有可用助手或所需设备 | 查看原因、检查设备 |
| 已暂停 | 服务端确认暂停 | 继续 |
| 执行遇到问题 | 确认失败，保留部分结果 | 查看原因；支持时重试 |
| 已完成 | 所属执行链路确认整体完成 | 查看结果 |
| 已取消 | 服务端确认取消 | 查看记录 |
| 状态待同步 | 连接中断或数据过期，附最后同步时间 | 重新连接 |

“状态待同步”是覆盖提示，不篡改最后已知执行状态；服务端可能仍在工作。“进行中”筛选包含排队、执行、等待资源和暂停等未结束任务，逐行保留具体状态。

待处理数量定义为 **有未解决事项的任务数**；详情再显示事项数，例如“1 个任务需要你处理 · 共 2 项”。审批按 approval ID 去重，提问按 question/message ID 去重。WAITING_HUMAN 且找不到具体事项时显示“等待原因暂不可用”，提供刷新/诊断，不能伪造批准按钮。确认提交成功后重新读取服务端状态，任务未必马上恢复。

## 8. 文件、设备、设置

**文件**：按最近产出排序，每项展示文件名、来源任务、时间和真实可用的查看/下载操作；文件失效明确标记。任务详情中的文件默认限定来源任务；全局文件页保留跨任务检索。

**设备**：分“可操作电脑”和“执行环境”。每项显示名称、最近心跳或同步时间、可用/忙碌/离线/未知及当前任务。节点在线不等于拥有可操作桌面，未配对或未实现的设备不能显示为在线。接入流程复用已有能力；Android Device Node 不列为可用功能。

**设置**：普通用户优先看到连接、助手、技能与工具、偏好与记忆；底部“高级”保留旧白板、看板、旧版协作、技术诊断等迁移入口。全局危险配置继续保留明确的作用范围和确认。

## 9. 空态、异常与适配

| 场景 | 页面表现 |
|---|---|
| 首次使用、尚未配置 | 引导连接工作空间；输入可保留为草稿，不能假装开始运行 |
| 已配置、没有任务 | 输入框 + 两三个可填入的示例，不显示一排 00 |
| 没有待处理事项 | 收起待处理模块；筛选显示“没有需要处理的任务” |
| 正在加载 | 骨架屏，不使用 0 冒充真实统计 |
| 部分接口失败 | 保留其他可用区域，失败区域有独立重试 |
| 连接断开 | 展示最后已知数据、同步时间，禁用审批和设备控制 |
| 设备离线 | 只影响依赖该设备的任务，不宣称全部任务不能运行 |
| 长标题、长结果 | 标题允许两行；完整内容在详情可读，不横向撑破页面 |

视觉：沿用品牌蓝，减少多层卡片嵌套；白色表面配浅灰蓝背景。正文 14—16px，标题 28—32px；状态采用文字 + 小色点，不能仅靠颜色区分；常用按钮至少 40px 高，键盘焦点清晰。

1024px 以下缩窄留白；900px 以下详情侧区下移；窄屏导航变成紧凑横排，输入与任务列表保持单列。弹窗需焦点约束、Esc 关闭及关闭后焦点恢复。生产版本验收需涵盖键盘操作、屏幕阅读器标签及 200% 缩放。

## 10. 技术落地边界

这不是把 Goal、Conversation、Task、Card 的 ID 混成一个字段。建议建立前端任务视图适配层，至少携带 `sourceKind + sourceId`、标题、最新活动、显示状态、待处理引用、结果引用、真实可用操作及原始对象链接。字段是提案，不是已有 API 合同。

会话按 conversation 聚合执行轮次，Goal 按 goal 聚合卡片与编排。两者没有可靠关联时分别展示，不按相似标题合并。独立白板卡片在建立真实归属前保留高级入口，不静默丢弃，也不伪装成某个 Goal 的步骤。

每种来源的能力不同：只有后端已支持的暂停、重试、取消才提供按钮。统一列表不能凭 UI 生成跨链路控制能力。详情、审批和产物必须保留源 ID；多 Kernel 的缓存和任务身份需包含当前连接身份，切换连接不得串用旧数据。

## 11. 实施顺序与验收

**第一阶段：降低入口复杂度。** 调整 App 导航与文案；提供统一任务页框架、准确待处理区；设备和高级入口可达；保留已有详情实现和历史链接。不在同一批改动中迁移数据库或删除执行链路。

**第二阶段：统一任务视图。** 明确 Goal/会话适配合同，聚合进度与产物；实现新建路由、精确跳转、可用操作和历史对象兼容。需确认所有来源的关联、提问与产物接口，缺失时补合同后实现。

**第三阶段：优化详情。** 对话与结果为中心，电脑按需展开，简化进度，逐步把旧高级页能力迁入合适位置。待真实验收后再评估是否移除旧导航兼容。

相关实施文件：`apps/desktop/src/App.tsx`、`pages/Dashboard.tsx`、`pages/Workbench.tsx`、`pages/Goals.tsx`、`pages/FilesMemory.tsx`、`pages/Settings.tsx` 以及新增任务视图适配层。具体拆分由实现阶段确定，不覆盖当前未提交改动。

验收标准：

- 主导航 3 项，设置独立；新用户不需理解 Goal、Pi、Kernel、白板即可提交任务。
- 首屏输入一次要求即可提交；点击任意任务到达对应对象，不只跳到通用会话页。
- 待处理区和筛选数量一致，覆盖多审批、提问、无详情等待与查询失败场景。
- 已完成结果在任务详情直接可见；文件可以返回对应来源。
- 旧会话、Goal、独立卡片和高级配置均能找回；切换 Kernel 不串数据。
- 暂停、重试、审批、接管显示与服务端确认一致；断连不假装在线或执行成功。
- 桌面 1366×900、1024×768 和窄屏无横向溢出；键盘可完成主流程。
- 实施时运行桌面构建、相关状态适配与交互测试；真实环境补验 Goal 和旧会话两条路径。

建议邀请 3—5 位不熟悉系统的人完成“创建任务、处理确认、找结果”三项操作，记录误入页面次数与是否需要解释概念。目标是三项流程都不需要讲解内部架构；此目标尚未开展实测。

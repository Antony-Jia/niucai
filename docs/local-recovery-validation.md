# 本地任务停滞与断线恢复

日期：2026-10-07。本轮完成优先项“任务卡住时可判断、可操作”和“断线后恢复权威状态”，同时补齐 Kernel 的等待上限及取消处理。未部署或修改远端生产环境。

## 客户端行为

- 保持现有浅色 UI，任务详情和 Computer 工作台共享阶段、等待原因、最后业务进展和 Kernel 允许的操作。
- 排队或执行阶段超过约两分钟没有业务进展时给出提示及下一步操作。审批、人工等待、终态、旧版 Kernel 和断线快照不显示运行停滞提示。此提示不改变任务状态，也不自动重试。
- 可手动刷新任务状态。任务、动作、审批或电脑查询失败时，任务控制禁用，避免使用不完整快照审批或恢复。
- 全局显示状态待同步。断线不推断任务已停止，保留最后已知状态；恢复 WebSocket 或成功切到事件轮询后，重新拉取任务、审批、电脑等已订阅快照，即使没有新业务事件也同步。
- 同步期间禁用任务控制、审批以及电脑接管/交还；查询失败的对应入口继续保持禁用。事件按 ID 合并和去重。
- 原生事件连接不再在 HTTP 轮询成功前宣称“轮询同步”；长时间没有任何 WebSocket 帧时主动退回重连和轮询。
- 保存的原生连接在启动时暂不可用，会继续尝试连接，不需要重新输入凭据；认证失效仍要求重新连接。

## Kernel 行为与配置

| 配置 | 默认 | 行为 |
| --- | --- | --- |
| `NIUCAI_MODEL_TIMEOUT` | 120 秒 | 覆盖一次模型调用的全部请求、重试和退避；超时取消请求，记录模型失败，并终止本轮任务 |
| `NIUCAI_RUNTIME_IDLE_TIMEOUT` | 300 秒 | 本轮执行持续没有新的业务进展时中断运行时；尚由该 Worker 持有的运行任务进入 FAILED，保存明确错误 |

通常应让运行时无进展上限大于模型总时限及动作时限。业务进展时钟不由租约心跳更新；Worker 使用单调时间计算监测间隔，不依赖机器时钟跳变。

暂停、停止或失去租约后，Worker 中断仍在等待的执行协程，并等待清理结束。Pi 保持原有“结束子进程后才释放会话锁”的规则。旧 token 不得写入新一轮状态。

外部动作仍遵守原有有界执行、数据库锁和 UNKNOWN 规则：已发出的副作用无法假定撤销；不确定结果必须人工核对。此次改动不添加自动任务重试，不绕过审批，不承诺已经执行的操作可以回滚。

无进展监测只针对已经被 Worker 领取的任务；Worker 未启动时的排队问题由客户端提示及远端诊断处理。

## 验证

- 本地独立 Linux 容器 SQLite：104 通过、3 项 PostgreSQL 专项跳过。
- 本地临时 PostgreSQL 17、独立网络、临时数据目录：107 通过；测试容器与数据库已清理，未使用现有业务数据库。
- 客户端 Vitest：19 通过，覆盖停滞提示边界、断线禁用、恢复后无新事件也同步任务/审批/控制状态。
- 桌面浏览器端到端：4 通过，使用本机 Chrome，覆盖七页、工作台、最小窗口和审批入口。
- Rust 1.98.1 原生单元测试：3 通过；Python Ruff 检查及格式检查通过。

Kernel 测试在已有本地镜像中使用 uv 安装测试依赖，挂载最新源码；没有连接远端服务器或真实模型、浏览器服务。浏览器端到端使用示例数据，不能替代远端桌面、真实模型和人工接管联合验收。

## 后续边界

本轮不宣称第二阶段全部完成。结果附件预览增强、隐藏页面预览刷新优化及真实远端接管恢复仍需后续验收。新客户端可连接旧 Kernel，但模型总时限和运行时监测需部署更新后的 Kernel 才生效。

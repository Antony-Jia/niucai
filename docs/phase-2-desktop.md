# 第二阶段：本地客户端体验与任务闭环

状态：实施计划，尚未全部实现。基线日期：2026-10-07。
本轮进展：L1/L2 已实现进度展示、服务端操作列表、提交防重复与失败重试提示；已具备旧服务兼容。真实服务器切换和三端联合验收尚未完成，L3–L8 仍按下表实施。
目标：用户始终知道任务在做什么、为何等待、如何接管或恢复，以及结果在哪里。
配套：[远端环境](phase-2-remote.md)、[Kernel](phase-2-kernel.md)。

## 当前基线

- Windows Tauri 客户端已连接远端 Kernel；Computer 三栏工作台及全部页面已统一浅色风格。
- Tasks 已可批准/拒绝当前任务的动作，运行任务有暂停和停止入口，暂停任务可恢复。
- Chat 转交可选择执行电脑，默认已注册的 Linux Computer；仍可选择纯推理。
- 未绑定任务可暂停后绑定电脑；工作台画面与任务绑定不一致时已有提示。
- Agent 模式已有每两秒刷新的只读浏览器截图；完整桌面操作通过 HUMAN 模式的 VNC。
- 已修复关闭桌面失败阻塞交还的前端路径；真实接管失败、残留窗口和重连仍需系统验收。
- Tasks / Computer 工作台共享进度区和控制入口，展示最后业务进展时间，按 allowed_operations 显示按钮。待审批/UNKNOWN 不显示普通恢复；请求失败保留状态并给出错误。

## 职责边界

客户端只展示 Kernel 的权威状态并提交用户操作。
不根据截图静止判定任务卡死，不自行改变任务状态，不自动批准高风险动作，也不把 VNC 连接失败等同于交还成功。
视觉沿用当前白底、浅灰侧栏、蓝色主按钮；不在本阶段重做布局。

| 编号 | 优先级 | 交付物与行为 | 验收条件 |
| --- | --- | --- | --- |
| L1 | P0 | 任务进度区对接 K1/K2，显示阶段、等待原因、最后进展时间 | 用户能区分等待模型、等待设备、审批、接管和断线；旧服务缺字段时有兼容提示 |
| L2 | P0 | 统一操作入口和状态反馈 | 开始/排队、暂停、继续、停止、重试各有明确可用条件；请求中防重复，失败可重试且有原因 |
| L3 | P0 | Chat 转交后定位新建任务与所选电脑 | 只创建一次任务；明确显示任务 ID/名称与电脑；纯推理不误显示其他任务的电脑画面 |
| L4 | P0 | 接管、打开桌面、交还的失败恢复流程 | VNC 登录失败/窗口失败后仍能交还；交还失败不显示成功；残留交互窗口需被关闭或明确处理 |
| L5 | P0 | 断线重连与事件补齐 | 隧道中断显示连接状态，不伪报任务失败；恢复后回放事件并刷新权威快照；审批不丢失、不重复 |
| L6 | P1 | 完成结果卡片与失败详情 | 展示摘要、最终页面、截图缩略图、查看/下载；失败显示所在步骤和已完成部分 |
| L7 | P1 | 只读观察状态与刷新优化 | 标记画面时间、旧画面、连接失败；隐藏页面停止轮询；查看不改变控制权或允许远程输入 |
| L8 | P1 | 窗口尺寸、可访问性与 Windows 原生验收 | 最小窗口可见关键操作；键盘可操作；原生构建下审批、预览、下载、接管均验证 |

## 状态与按钮约定

| Kernel 状态/原因 | 本地展示及操作 |
| --- | --- |
| PENDING | 已排队/自动开始；展示设备或控制权阻塞原因，可暂停/停止 |
| RUNNING | 展示实际阶段与进展；可暂停/停止，不显示会重复启动的开始按钮 |
| PAUSED | 展示暂停原因；条件满足后继续，可停止 |
| WAITING_HUMAN / approval | 显示动作内容、风险和批准/拒绝；“继续”不能代替批准 |
| WAITING_HUMAN / computer required | 选择/绑定电脑，再继续 |
| WAITING_HUMAN / UNKNOWN | 引导查看实际结果并核对；不能用普通重试掩盖不确定副作用 |
| FAILED | 展示可理解错误；Kernel 允许时重试，保留原会话/记录 |
| COMPLETED / CANCELLED | 展示终态与已生成产物，隐藏过期等待提示 |
| 客户端断线 | 显示“连接中断，服务器任务状态待同步”；不推断服务端停止 |

具体按钮可用性以 Kernel 定稿的 allowed_operations 和服务端校验为准。
批准、停止、核对 UNKNOWN、接管/交还分别是不同操作，不能合并成含义不明的“继续”。

## 与另外两端的依赖

- 已对接 Kernel K1/K2 的可选进度合同；旧服务显示兼容提示，不从事件数量猜执行进度。任务同步失败时明确显示最后已知状态并禁用控制。
- K6 的产物摘要供结果卡片使用，已有认证下载保持可用。
- 远端提供稳定隧道和服务端日志；本地只保存经脱敏的诊断信息，不把 Token/VNC 密码写入 URL。
- 若探索完整桌面只读视频流，需远端验证服务端只读权限；仅屏蔽前端鼠标不能作为只读保证。

## 验证与交付

界面回归覆盖：Chat 选择电脑 -> 转交 -> 定位任务 -> 审批 -> 暂停/继续 -> 停止/失败重试 -> 查看产物。
通过可控事件验证断线、补齐、请求失败与重复点击；再做 Windows Tauri 原生验证，不仅测试 Vite 网页。
真实跨端验收使用固定百度图片任务，执行中接管并交还，关闭客户端再打开，仍看到真实进度及最终截图。

通过条件：所有等待有明确解释和下一步操作；关键按钮在最小窗口可用；查看画面不抢控制权；断线不丢审批。
本阶段优先 Windows，不扩展移动端功能或桌面自动操作能力，不引入新的审批放行策略。

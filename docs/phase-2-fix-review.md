## 必须补齐的问题

### 1. 原任务实际续跑没有被验证

`docs/APP-RESTORE-DRILL.md` 明确源任务在备份前已经 COMPLETED。`scripts/app-restore-drill.sh` 的 D 段只打印恢复后的任务字段，随后无条件输出 checkpoint survived；没有断言会话标识、检查点内容或成功续跑。

不能把“完成记录能查询”和“拒绝恢复已完成任务”标成“原任务能够继续”。应增加非终态任务：完成第一次经批准的文件写入后，停在真实人工等待；备份并恢复到独立栈，合法恢复后完成后续读取及最终回复。核对同一 Pi 会话/提交、已有动作标识以及实际 adapter 调用次数或外部效果，证明先前写入未再次派发。此流程不依赖浏览器。

### 2. 测试脚本仍丢失 pytest 退出码

`scripts/run-kernel-tests.sh:86` 在容器内使用 `pytest ... | tail -45`；内层仅设置 `set -e`，没有 `pipefail`，外层取得的是整段容器命令的退出码。最后检查 rc 不能补回已丢失的 pytest 状态。

本机通过模拟 Docker 命令、保留原脚本的 pytest 管道做反例：模拟 pytest 打印 `1 passed in 0.01s` 后退出 7，原交付脚本仍返回 0 并输出成功摘要。

修复：在内层启用 pipefail 或显式保存 PIPESTATUS，可靠传出 pytest 状态；最好同时输出 JUnit 报告。补测正常摘要之后非零退出、超时、空日志。现有反例脚本实际执行的四个测试场景是失败、零测试、全部跳过、路径不存在，没有执行其注释声称的超时和空日志场景。

### 3. no-replay 脚本遇到服务错误仍宣布通过

`scripts/verify-no-replay.sh:84` 对意外 HTTP 状态只输出 note；任务查询及动作查询失败也没有完整的失败判定。

本机使用纯模拟 curl/docker，令 resume 返回 HTTP 500、动作快照不变，原脚本仍输出 `NO-REPLAY VERIFICATION PASSED` 并返回 0。没有连接真实服务器或 Docker 服务。

修复：要求任务查询和数据库查询成功、任务与预期状态匹配；终态保护场景必须返回预期 409，其他状态均失败。真正续跑场景须接受合法恢复、等待推进到预期终态，再验证无重复派发。动作行不变本身不能证明外部操作未重复执行。

### 4. 浏览器协议证据强度不足

`scripts/cdp-protocol-probe.sh` 每发送一条 CDP 请求只读取下一条消息，没有按请求 ID 匹配响应；事件推送可能被当成成功。包内 A 日志对 attachToTarget 打印的是 `Target.targetInfoChanged` 事件，并非 id=90 的成功响应。

因此只能确认建立连接且收到部分消息，不能据此排除 Chrome 或整个协议链路。C 日志只启用 `DEBUG=pw:browser`，没有协议级命令/响应日志，仍不能定位最后阻塞的 CDP 请求。

修复：原生探针等待与请求 ID 匹配的响应，将事件单独记录；超时/协议错误返回非零。增加 Playwright 协议调试记录和单调时间耗时；用同一端点比较最后成功请求、失败请求与 sessionId。保留“根因未定位”，撤回“七项完全排除”。

### 5. 备份及构建的剩余缺口

- backup 仍硬编码读取 `/opt/niucai-remote` 配置，即使选择隔离项目；应采集实际项目的有效配置和版本。
- `chmod -R 600` 仍应用于配置目录；目录需要 700、文件需要 600。
- 必要卷缺失仍在 backup 阶段 SKIP；Worker 重启失败被忽略，输出却可能称已重启。应拒绝不完整备份，恢复原运行状态并检查结果。
- 只停 Worker 不能独自证明全部写入被暂停；说明 API、人工操作及浏览器写入如何被限制，以及备份窗口内无其他写入的证据。
- build 虽增加信号清理，仍缺少普通错误退出时的 EXIT 清理；锁重写或前置步骤失败后仍可能留下临时修改。
- 两个备份反例生成清单时在被扫描目录内写 `.sums`，随后删除它，可能使“损坏 dump”和“缺凭据”场景同时含有额外的缺失清单文件。应将临时清单移出被扫描树，并断言预期失败原因，避免其他错误让反例虚假通过。
- 附件脚本实际用 grep 检查包含预期文本，不是文档声称的逐字节断言；改用 cmp 或固定 SHA256。

## 构建报告的证据边界

- build-images.sh 的缓存提示确有误导：目录存在只改变输出，不改变实际 Dockerfile 的 uv 来源。
- 宿主状态文件记录约 3.9 GiB 总内存、455 MiB available、无 swap，以及历史高 load，足以说明构建余量紧张。它不是每次构建失败时的 OOM 记录。
- 137、Killed 只能说明进程受到 SIGKILL；记录中也存在主动终止，不能单凭退出码认定内核 OOM。需要对应时间的内核/cgroup OOM 证据才能落实该归因。
- 新缓存安装单个包与构建完整锁定依赖不是同条件对照；缺少仅改变缓存目录、保持资源/源/依赖一致的对照，不能认定“缓存毒化”已证实。
- “D 状态因无 swap 永远无法回收”并未由现有记录证明。不要直接执行文档中按全局命令字符串匹配的 pkill；应按具体构建作业或容器身份处理，避免影响其他任务。

这些限制不妨碍采取异机构建：该方案能降低运行服务器上的构建压力，不依赖先确定唯一根因。

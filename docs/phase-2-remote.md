# 第二阶段：远端环境与运维

状态：实施计划，尚未全部实现。基线日期：2026-10-07。
目标：环境可重建、故障可定位、数据可恢复；为 Kernel 的恢复测试提供真实设备。
配套：[Kernel](phase-2-kernel.md)、[本地客户端](phase-2-desktop.md)。

## 当前基线

- 单服务器、单 Worker、单 Linux Computer；真实浏览器搜索和截图已由用户验收。
- PostgreSQL、Pi JSONL 会话、workspace、浏览器 profile、下载目录、桌面 home 持久化。
- API 与桌面中继只监听服务器回环，通过 SSH 22 转发；CDP 仅在 Docker 私网可达。
- 浏览器原始 CDP 为容器回环 9222，经同容器中继以 computer:9223 提供给 API/Worker。
- 现有服务器是 CentOS 7。系统迁移需要独立维护窗口，不在本阶段直接替换系统。
- 已部署环境曾使用本地构建变体和补丁镜像。仓库部署模板与现场配置需审阅合并，不直接覆盖 .env 或执行 reset。

## 职责边界

远端负责 Docker、网络、存储、备份、监控、发布和故障注入。
任务状态、审批、幂等与是否重试由 Kernel 决定；远端脚本不得自行把 UNKNOWN 改成成功，也不得自动批准动作。
本地客户端负责桌面展示与人机交互，不在服务器安装 Windows 客户端。

## 实施清单

| 编号 | 优先级 | 交付物与行为 | 验收条件 |
| --- | --- | --- | --- |
| R1 | P0 | 形成固定 Git revision、镜像 tag/digest、Compose 配置的发布清单；统一构建脚本 | 新建隔离部署目录能从源码构建；无需旧源码 ZIP、临时补丁层或手工 docker cp |
| R2 | P0 | 检查 API、Worker、CDP、VNC、数据库、空间与权限的诊断脚本 | 明确区分进程存活、接口可用和真实动作成功；日志不输出凭据 |
| R3 | P0 | PostgreSQL + Pi 会话 + workspace 等卷的协调备份与恢复手册 | 在隔离项目恢复，任务、审批、会话与截图相互对应；恢复后不会重复执行已完成动作 |
| R4 | P0 | 维护窗口发布与回滚流程 | 先暂停领取新任务、等待有界动作结束，再更新；失败可回退镜像和配置；不删除数据卷 |
| R5 | P1 | 服务健康与磁盘告警、日志轮转 | 记录 Worker 心跳、模型超时、CDP/VNC 失败和磁盘阈值；故障发生后能指出组件 |
| R6 | P1 | 故障注入记录与验收证据包 | 覆盖 Worker 重启、API 重启、浏览器退出、网络短断；记录时间、版本、task/action ID、恢复结果 |

## 备份合同

至少覆盖：PostgreSQL、pi_sessions、workspace、browser-profile、downloads、desktop-home，以及加密或受限保存的部署配置和凭据。
数据库与 Pi 会话须来自同一个一致性窗口。先停止新任务领取并静默 Worker，再备份；不能把任意时刻的两个快照拼接。
秘密备份不进入 Git、不放进模型可读 workspace，不发到聊天。恢复演练使用独立目录、Compose 项目、端口和卷名。

当前模板使用固定卷名与网络名；隔离恢复必须逐项改名，不能只改 Compose project name。
恢复完成后先验证记录一致性与访问权限，再允许 Worker 运行。Pi 会话缺失时维持明确失败，不通过删除 checkpoint 假装恢复成功。

## 交付给 Kernel 的接口与证据

1. 私网 CDP 和桌面中继的稳定地址、容器健康信息；不把无认证 CDP 暴露公网。
2. 发布版本、镜像 digest、存储卷清单、备份时间与回滚步骤。
3. 按约定时间执行的故障注入记录；Kernel 提供关联 task/action ID 与预期状态。
4. 诊断脚本只读；重启、恢复数据和故障注入必须按维护范围执行。

## 跨端验收场景

使用固定任务：百度搜索金城武照片，打开图片结果、保存截图并汇报。
正常流程保留人工审批；另外在专用测试任务中分别接管/交还、关闭客户端、断开隧道、重启 Worker。
同时只注入一种故障。对已经发起的可能有副作用动作，接受 UNKNOWN + 人工核对，不要求盲目自动重放。

通过条件：已完成动作不重复、待审批动作不绕过、数据不丢失，故障与恢复都有可追溯证据。
不能仅凭容器 healthy 或一次 healthz=200 判定阶段完成。

## 执行顺序与非目标

先完成 R1/R2，再完成 R3/R4，最后做 R5/R6 与跨端演练。
本阶段不扩展多 Computer、不引入 GPU、Kubernetes 或多 Worker，不调整现有 Hermes 的模型/服务配置。
完整桌面只读视频流可以做独立原型，但不阻塞任务恢复主线，不能用可交互 VNC 冒充只读观察。
